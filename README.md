# floodforest

Code for the study "Do riverbank forests limit the lateral reach of Himalayan debris floods?".
It maps flood impact from Sentinel-1 and Sentinel-2, measures how far the impact reached
across each riverbank along transects, and relates that reach to the forest on the bank.
The analytical rules are in `CURSOR_BUILD_SPEC.md` (section 14 overrides earlier sections);
settings and user decisions for every event are in `config.yaml`.

To review the results without running anything, start with [REVIEW.md](REVIEW.md).

## Setup

Requires Python 3.11 (tested with 3.11.9). From the repository root:

Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
```

If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once,
then activate again.

Linux or macOS:

```sh
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

Check the install with `python -m floodforest.cli --help`.

## Earth Engine

Earth Engine is needed only for the `fetch` step (and `placebo`, which fetches the placebo
images). The tests and every later step run on local files. A full fetch needs several GB of
free disk: the current `data/` and `outputs/` folders take about 5 GB.

A reviewer without Earth Engine access can still run the tests from a fresh clone, and can
run `stats` given a copy of the author's `outputs/<event>/` and `outputs/<event>_placebo/`
folders (they are not in the repository). The reports, tables and figures in `results/` can
be read without running anything.

1. Register a Google Cloud project for noncommercial Earth Engine use.
2. Authenticate once: `earthengine authenticate`. The credentials are stored in your user
   profile, outside the repository. Never copy them into it.
3. Set `ee_project` in `config.yaml` to your project ID.
4. Before fetching, check that the event's centerline (`data/<event>/centerline.geojson`) exists
   and is marked verified in `config.yaml`.

## Steps

Run each step with `python -m floodforest.cli <step> --event <event>`, in this order:

| Step | What it does |
|---|---|
| `fetch` | Downloads the rasters from Earth Engine into `data/<event>/rasters/` |
| `label` | Builds the impact labels (optical, radar, combined) |
| `transects` | Lays out stations and transects along the centerline |
| `profiles` | Samples elevation, label and forest along each transect |
| `table` | Writes the analysis table `outputs/<event>/transects.csv` |
| `stats` | Fits Model A and Model B, all sensitivity runs and the verdict (`outputs/<event>/stats/`) |
| `placebo` | Runs the same pipeline on two years with no flood (`outputs/<event>_placebo/`). It refuses to run unless `flood_check.status` under the event's `placebo` block in `config.yaml` is `confirmed` |
| `validate` | Draws the blind validation sample, stratified by forest group |
| `validation_subset` | Draws, from the sample, the stations still to digitise so that each forest group reaches the same count |
| `edges` | Reads the hand-digitised edge points and snaps them to the sample transects |
| `compare` | Compares digitised and computed reach (`results/<event>/` or `results/` for Melamchi) |
| `report` | **Not built.** The HTML report of spec section 10 does not exist yet |

`stats` reads the placebo and validation results, so run `placebo` and `compare` before the
final `stats` run.

The validation sample and the subset were each drawn once with a recorded seed (lende2025:
sample seed 42, subset seed 43, both drawn on 2026-11-12). The seeds, rules and dates are in
`config.yaml` and the event's provenance, and both steps refuse to draw again.

## What is tracked and what is regenerated

Tracked: the code, tests, `config.yaml`, the verified centerlines and exclusion polygons,
Melamchi's validation points, and the result files under `results/` (reports, tables,
figures). Everything under `data/` (rasters, intermediate tables) and `outputs/` is
regenerated by the steps above and is not tracked. Rasters, GeoPackages, QGIS projects,
caches and credentials are ignored.

## Rerunning lende2025

With Earth Engine set up:

```powershell
foreach ($s in "fetch","label","transects","profiles","table") { python -m floodforest.cli $s --event lende2025 }
python -m floodforest.cli placebo --event lende2025
python -m floodforest.cli edges --event lende2025
python -m floodforest.cli compare --event lende2025
python -m floodforest.cli stats --event lende2025
```

Do not rerun `validate` or `validation_subset` (they refuse). `edges` and `compare` need the digitised points in `data/lende2025/validation/` (copies are in
`results/lende2025/validation/`). Without new downloads, `stats` alone reproduces the
statistics from an existing `outputs/lende2025/` table.

## Tests

```powershell
python -m pytest -q
```

Most tests use small made-up data. A few read the local outputs and are skipped when those
are not present.

## Checking that Melamchi's results are unchanged

`results/melamchi2021_checksums.sha1` lists the SHA-1 of every committed Melamchi result file.
From the repository root:

```sh
sha1sum -c results/melamchi2021_checksums.sha1
```

Every line should end in `OK`. The two report hashes are `STATS_REPORT.md` dff0fd71… and
`PLACEBO_REPORT.md` a94c4381….
